SpellVision · consistency and robustness audit

The defects were second copies of rules already applied correctly once

A full-repository survey against Doc 50's build standard. Eleven of the top twenty fragility findings were places the codebase already knew the right answer and applied it once — in six cases in the same file as the correct copy. The fragility was never ignorance of the rule; it was the absence of anything that carried the rule to the second site.

01The finding

Doc 50 rule 5 says nothing else in the tree may decide the same question differently. It was failing at the level of process rather than code: each rule had been enforced at the site where its defect was found, and nowhere else.

The ratchets meant to prevent this had the same shape as the bug. The seed sweep was scoped to three files named in a tuple, while five violations sat outside it. The endpoint sweep globbed python/*.py — flat — so two whole packages were invisible to every sweep in the repository. numeric_option was a correct helper with no sweep behind it and 87 sites of the defect it prevents. And nothing derived the set of message types actually emitted, so nine shipped unregistered.
This became Doc 50 rule 10: a rule is applied to the tree, not to the site. A fix without a tree-wide ratchet was out of scope for the pass.

03The failures reported success

The pattern that made all of this survivable-looking. Almost none of these announced themselves.

A job that failed before STARTING re-ran and re-failed on every launch, forever

The queued state permitted only two hops, and the failure path discarded the transition's return value. The item reverted to queued, was persisted, was popped from pending so it never drained — and manifest recovery rebuilds pending from exactly that state. Fourteen raise sites reached it; one sits eight lines below the comment describing the hazard.

Cancelling did not cancel

There was no interrupt call and no queue-delete anywhere in the repository. Cancelling stopped SpellVision polling while ComfyUI rendered to completion holding 20+ GB of VRAM.

An auth refusal arrived as ok: true

The type was unregistered, so it was wrapped in a warning envelope whose own ok was true — and the C++ parser had no case for that envelope either. Discarded twice.

The highest-leverage single line in the pass was flipping that envelope's ok to false. An unknown type is now a failure, which converts every future unregistered type from silent to loud.

Four families shipped an alphabetical default

sdxl, pony, illustrious and stable_diffusion advertised ddim + karras because the resolver fell through to sorted(samplers)[0] when no default was declared — the default on 112 checkpoints. An allowlist without a declared default now raises at import.

A control shown exactly where it is ignored

VAE Tiling appeared only in the WAN dual-noise route, which never reads the key; the one builder that honours it is the wrapper route, where the checkbox was hidden. Looking for the rule rather than the instance found the same defect with the sign flipped — the cockpit sends six WAN split keys the dual-noise builder reads none of, so three more controls were inert. One edit would have fixed a checkbox.

Native renders reported 0.0 GB of VRAM

On a native route the weights are in ComfyUI's process, so torch in the worker sees nothing; on the hosted route the render happens on someone else's hardware. All three wrote the same zero into a field every other route fills with a real measurement — and the history rows and bottom bar read it as one.

04What only the sweeps could find

Four results that exist because the rule was applied to the tree rather than the site.

Dead code satisfies ratchets

A request key was reported as having a reader — in a package nothing imported. A live rule was reporting a pass on the strength of code that could never run. Deleting the package is what revealed the key had no live reader at all.

An omission has no syntax

One phase routed nine text-encoder sites through a single resolver and drove that sweep to zero. Four krea2 loaders passed no device at all, and a rule matching a hand-written value cannot see an absent one — so the OOM-vs-fits bug survived the phase that was fixing it. Widening the rule to match the class found two more the moment it ran, including the family with three encoders and the most to gain.

Zero can mean the shape is wrong, not that the tree is clean

The zero-is-sayable rule was written for the denoise defect, went to zero, and stayed there for two phases while eight copies survived as guards rather than as the default-expression it matched. A stated 0.0 silently became 0.6, and an absent value was indistinguishable from a stated zero because both took the same branch.

Five copies, and grep could only find four

The project-root walk was hand-written five times. The fifth shares no substring with the other four, so no name-keyed search could reach it — the sweep found it by what it does. One copy searched depth 7 where the rest searched 8, so a build eight levels below the root would have had four components find the project and the fifth fall back to the working directory, with no error, because the fallback is a valid path.

The reason it had never fired was a property of the build directory, not of the code.

The one found by moving the product, not by reading it

Every other finding here came from reading the tree. This one came from pointing SpellVision at a ComfyUI on a second machine and watching which halves followed it.

Everything that asks the endpoint worked unchanged — the resolver's precedence chain, a 904-class /object_info fetch over the wire, the graph builder, and a 1.28 MB render pulled back through /view. Six of six, first run.

Everything that asks the disk was wrong. And the hazard is not that the local output directory comes back empty — it comes back full, of the previous local session's renders, so a gallery scanning it after a remote render shows an old image as though it were the new one. Nothing errors. is_local_endpoint's own docstring already listed “reading an output from disk” among the things that must check it; none of the ten readers did.

The security pass had the same shape

Three HIGH and three MEDIUM findings, and every one was a rule already applied once: the integration tier bounded the command but not the fields those commands honour; the bind address was held closed while the peer address on a shared machine was trusted; model downloads sanitised their filename while render downloads took their extension from whichever machine served them; the queue manifest redacted the token while the job archive three lines away persisted it.

The request-schema ratchet, run once, named four uncovered keys the audit had not. The session-secret rollout touched every client in one commit because the test fixture is a client — 1670 tests presented the secret correctly on the first run.

05What this audit is not

A rule's precision is part of its design, so the over-counts are recorded rather than quietly corrected.

RuleNaive scopeRealWhat the noise was
wire types registered3010every {"type": …} literal — but one is a CLIPLoader input and another an acceleration descriptor
one project-root resolver31a climb for the icons directory, and a three-level climb to derive the Comfy root, each merely sharing a file with the sentinel
local output only for a local endpoint1310a header declaration and two definitions — declaring the accessor is not reading the directory
A rule that flags two false positives per true one gets bypassed, and then it protects nothing. Scoping the second rule to proximity rather than co-residence took it from three to one.
Both rules written in this pass were silently broken on their first run, and both looked exactly like success. The dispatch-shape guard — written to refuse any shape the command extractor cannot read — missed one of the four shapes it claims to catch: the silent under-report it exists to prevent, inside the thing preventing it. The project-root rule had a mangled escape that left a literal backspace in its compiled pattern, so it matched nothing and reported a clean tree; fed the exact code it was written for, it stayed silent.

Both were caught by feeding each rule every shape it claims to catch, and asserting it stays quiet on the shapes actually in use. A guard nobody has watched fail is a guess about what it does.
Then the fix for an over-count created a false negative, which is the harder failure. Scoping the newest rule away from definitions matched return chooseComfyOutputPath(); — a real read — because return sat where a return type would. The rule went from 13 to 9 and looked better. Tightening manufactures a false negative as readily as looseness manufactures a false positive, and the negative is the one nobody notices, because a rule reporting less always looks like progress. It was caught by asserting the exclusion filter in both directions: what it must skip, and what it must never skip.

The meta-test separately refused the same rule for selecting its sources by file extension — the same prohibition as naming a file. The harness rejecting its own author is the strongest evidence here that the pattern is enforced rather than described.
And one planned item was simply not needed. The plan's premise that a measured 6.3× accel-LoRA speedup was never applied turned out to be wrong — it is applied. Reported as wrong rather than turned into work. Checking it found the real defect next door: the accel LoRAs were paired to the t2v variant regardless of command, so i2v runs loaded t2v LoRAs.

The third state is the whole argument. Before the harness, one seed site was not compliant, not violating, and not a documented exception — it was merely out of scope, which is how a defect hides in plain sight.
And then the C++ suite could not say why it failed. Breaking an assertion on purpose turned ctest red correctly and printed <end of output>. The binaries are console subsystem and still wrote zero bytes to both streams: Qt logs to the debugger when it cannot see an attached console, and ctest runs every test through a pipe. All five Qt tests had been in that state since they were written. One environment variable fixed it — and the only way to find it was to make a test fail on purpose.

07What was deliberately not done

Each with the reason, because an omission without one is indistinguishable from an oversight.

  • The 568-line command dispatch was not turned into a dict. Measured first: the existing extractor and an AST reader agree exactly on 125 commands — no gap today. So the class of failure was closed instead, without restructuring live protocol dispatch where branch order is load-bearing. The extractor now refuses any shape it cannot read.
  • MainWindow was not split by line count. Clustering its 102 methods by shared member field gives one component of 67 methods and 87 fields — there is no seam in the blob. But nine methods touch no member field at all, and three form a closed unit: the request builders, 321 lines deciding what the worker receives, reachable by no test. Those moved. The header went from 443 to 437 lines — a small number, and the honest one. The gain is 24 test cases over defaults that had never been asserted.
  • The five family namespaces were pinned, not merged. They sit at different layers, and merging them would be applying a rule at the wrong level — this audit's own subject.
  • Two empty sampler tables were not filled by copying a neighbour. Flow matching makes the obvious copy wrong for one, and the other is unrouted. An inert row that looks authoritative is worse than a gap.
  • Flux's pinned CFG and remapped denoise were not normalised to match six neighbours. Both were calibrated deliberately.
  • The krea2 inpaint topology was not forced into the t2i shape. Sixteen nodes against ten; they differ because the work differs. Only the loader block — the part that was genuinely identical, and the part the defect lived in — was merged.
  • TeaCache was not wired. Its win is assumed and has never been measured in this repository, and it is blacklisted on one of its three builders. Rule 1 says a heuristic ships with a number.

Since the pass — the tree as of 2026-09-03. The table above is the record of one pass and stays as it was measured. What it grew into: Python tests in 176 files, 20 C++ tests run by ctest, and 19 sweep rules with 15 at zero on a total baseline of 74. The audit's own documents were the last unswept surface: four of the modules this pass deleted were still on the architecture map four passes later, and the fix is the nineteenth ratchet rather than nineteen corrections. The newest entry is the same shape one layer out: the upscale graft searched for the literal SaveImage, so every video family's CreateVideo sink was invisible to it — no upscale, and no complaint. The sink table is now a property the builders are held to.

The open items, stated as items rather than as a clean bill:

  • No CI. The hook is the floor, not the ceiling. Closed 2026-08-31 — the hermetic lane runs on two platforms and ctest runs on Windows. The hook is now the fast floor, not the only one.
  • 55 request keys with no reader — a backlog with a decision behind each one.
  • The command dispatch is still 569 lines. Its ratchet is exhaustive; its shape is not improved.
  • MainWindow is still 6641 lines over one coupled component of 87 fields. The next honest move there is to break the coupling, not to move more lines.

Every defect in this audit was a place where the codebase already knew the right answer and applied it once. That is why the deliverable of each fix is the property, and the fix itself is only its evidence.
