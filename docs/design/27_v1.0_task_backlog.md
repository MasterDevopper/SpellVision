### 2.3 — CORRECTION 3: Seed random-as-checkbox
UI = a **"Random" checkbox**. Checked → field shows the random sentinel + locks (no typing). Unchecked → user types an explicit seed. The checkbox is one control; the injected value routes through the family-aware layer.

**Grounded (2026-07-18):** the random sentinel **is** builder-dependent, but favorably: **no builder uses a node `-1`** — every path takes an explicit **int** seed, with *defaults that vary* — Wan builders `req.get("seed") or ... or 1` (default **1**), Mochi/Hunyuan default **0**, wan-dual `_int_or_default(seed, 0)`, diffusers path `torch.Generator().manual_seed(int(req["seed"]))`. So:
- **"Random" = a CLIENT-generated random int**, injected as the seed — uniform across ALL current builders (none want `-1`). Do **not** assume `-1`.
- The per-family wrinkle is the *absent-seed default* (0 vs 1), which the checkbox makes moot by always sending an explicit value.

Scope:
- **UI control** · *what:* the Random checkbox + sentinel-display + field lock · *why:* the requested UX · *blocker:* none (cockpit widget work).
- **Per-family sentinel resolution** · *what:* confirm each builder takes an int seed (grounded: yes) and route the client-random-int through the family-aware layer; keep the hook per-builder in case a future family needs a node `-1` · *why:* correctness without assuming `-1` universally · *blocker:* none major — the value is uniform today; the routing hook is the future-proofing.
